## 3. 研究背景

当前总目标不是做一套独立的 `EbookPlus` 系统，而是确认：

`Ebook` 与 `EbookPlus` 是否能够统一到同一套业务逻辑中。

这里的“统一”特指业务语义统一，而不是底层取页方式必须完全一样。

允许不同：

- SVG
- img
- background-image
- 配置来源

不允许不同：

- 书籍身份语义
- 云库探测语义
- 缺书上报语义
- 整本贡献语义
- 元数据 `0.dat` 语义
- 维护流程语义

## 4. 当前已知事实

以下事实已经成立，不需要重复证明，但可以在研究中进一步补强证据。

### 4.1 真实书号

- `overview` 书架中 `thumb/13915` 这种数字是“真实教材编号”
- `overview` 书架中 `thumb/5917` 这种数字也是“真实教材编号”
- `digi4school.at/ebook/24s...` 是中间路由 token
- `digi4school.at/ebook/25s...` 也是中间路由 token
- `portal.oebv.at/DFS-...` 是最终 viewer token

结论：

- 最终 `portal` URL 不能直接等价于真实教材编号

### 4.2 EbookPlus 至少有两种 viewer 子类型

#### A. img 型

已知特征：

- 没有 iframe
- 没有 canvas
- 存在显式 `settings-json`
- 页面直接存在：
  - `img[src="content/pages/page_xxx/Scale1.png"]`
  - `data-page-wrapper`
  - `data-page-overlay`
- `settings-json` 中包含较完整的 pages / resolutions / titles / total / mapping

#### B. background-image 型

已知特征：

- 没有 iframe
- 没有 canvas
- 也存在显式 `settings-json`
- 页面图像来自：
  - `background-image: url('content/pages/page_xxx/Scale1.png')`
  - `background-image: url('content/pages/page_xxx/Scale2.png')`
  - `background-image: url('content/pages/page_xxx/Scale4.png')`
- 但页面数据并不主要放在 `settings-json` 中，而是分散在 HTML 预渲染结构与外部配置里

### 4.3 页码体系

`EbookPlus` 页面中已确认存在与普通 `Ebook` 相似的页码标签体系，至少包含：

- `U1`
- `U2`
- 正文数字页
- `U3`
- `U4`

结论：

- 页码输入层理论上可以与普通 `Ebook` 共用

### 4.4 当前未解决的问题

以下内容当前仍未确认：

- 标题的真实来源
- 最终 `portal` 页是否能独立恢复真实教材编号
- 两种 viewer 是否同源
- 资源页索引与逻辑页索引的统一规则
- 是否存在章节/目录数据源

补充：

- 已确认“两个样本都没有显式 settings-json”这一旧假设是错误的
- 正确结论应为：两个样本都有 `settings-json`，但其内容结构与信息完备度不同

## 5. 研究问题

本任务只回答以下 6 个问题。

### 5.1 资源 URL 构造规则

请查清：

- `img 型` viewer 中，页面资源 URL 如何构造
- `background-image 型` viewer 中，页面资源 URL 如何构造
- `Scale1 / Scale2 / Scale4` 的选择逻辑是什么
- `logicalPage -> assetIndex` 是否有统一规则
- 哪些信息来自 DOM，哪些信息必须来自 JS/runtime/network

### 5.2 viewer 子类型分流条件

请查清：

- 两种 viewer 是否属于同一套前端实现
- 如果是同一实现，分支条件是什么
- 如果不是同一实现，入口差异是什么

### 5.3 标题来源

请查清真实书名从哪里来：

- JS 对象
- 初始化脚本
- 请求响应
- runtime store
- 其他隐藏数据源

必须给出可定位的对象路径或字段路径。

### 5.4 页码 / 总页数 / 偏移来源

请查清：

- 总页数从哪里来
- `U1/U2/.../U3/U4` 标签从哪里来
- 逻辑页与资源页之间的偏移/映射从哪里来
- 这是显式配置，还是运行时计算

### 5.5 真实 bookId 来源

请查清：

- 在最终 `portal` 页中，是否还能恢复真实教材编号
- 如果能，来源路径是什么
- 如果不能，是否必须依赖书架入口桥接

### 5.6 目录 / 章节来源

请查清：

- 是否存在章节、目录、outline、toc 等结构化数据
- 如果有，来源是什么
- 如果没有，明确写“未发现目录源”

## 6. 研究范围建议

优先级从高到低如下：

1. 页面源码中直接可见的配置与结构
2. 页面引用的外部 JS bundle
3. Network 中的文档 / XHR / fetch / json 响应
4. runtime 中可定位的对象

不建议浪费时间的方向：

- 重新解释已有控制台结果
- 对产品策略做大段评论
- 直接提出“先这样凑合开发”的方案
